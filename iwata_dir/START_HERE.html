01

付属する気象で、最初の一飛行

目標：候補を一つ作り、軌道と着地点を表示する。最初は機体・地点・日時を変更せず、保存例を使います。

INPUT気象と候補どの場・どの条件で飛ばすか
RUN計算する固定した入力で飛行を解く
VIEW結果を選んで読む草案と計算時の条件を区別
SAVE計画を保存次回、同じ結果に戻れる
  1. 実計算の画面にする

    上部の 打上げ計画 → 表示するデータ で 保存気象・実計算 を選びます。

    人工データの操作模型とは別の、取得済み気象による計算画面になります。
  2. 保存例から候補を作る

    共通の準備 → 気象の準備 → 保存済みの気象 を開き、北海道・保存GFS例 の この保存例から候補を作る を押します。

    例の放球条件を持つ候補が増えます。「選択候補へ適用」は既存候補の気象を替える操作で、最初の候補作成とは別です。
  3. 一飛行の設定を確認する

    作成した候補を選び、条件を編集 を開きます。標本の作り方 の計算方法を 指定条件の一飛行（n=1） にします。

    この段階では日時を「今日」に変更しません。付属例の気象は過去の固定された時間窓です。
  4. 計算する

    この条件で計算 を押し、完了状態と地図を確認します。

    成功すれば軌道と着地点が表示されます。一飛行なので、50・90・95%の分散帯がなくても正常です。
  5. 詳細を見て、保存する

    この候補を詳しく → で高度・速度などの履歴を見ます。上部の 計画を保存 を押します。

    結果を見られたら一巡完了です。次は下の「一変量の仮幅」で複数標本を計算できます。
付属例は「今日の予報」ではありません。

和歌山の保存GFS例と東海の保存JRA-3Q解析例も選べます。まず動作を確かめるための条件であり、実機の推奨設定ではありません。

02

条件の幅・打上げの延期を比べる

まず一つの固定気象に対して、機体条件を一つだけ変えた仮感度を見ます。

一変量の仮幅：入力 → 固定 → 実行 → 表示

候補の 条件を編集 → 標本の作り方 で 一変量の仮幅を共通標本で調べる を選びます。

最初の下端と上端は同じ値です。変更が必要です。

下端 < 上端 と、空でない 理由 の両方が必要です。「仮幅の下端・上端を…」という文が出ている場合、それは入力を直すためのメッセージです。元量を変更したときも下端・上端が同値へ戻るので、改めて幅を入力します。

操作確認用の例：北海道の保存例／破裂方式が高度指定の場合
入力欄入れる値意味
変える元量破裂高度（m）高度を指定する破裂方式で使います。
下端 / 上端29000 / 30000この間の一様分布。実機の推奨幅ではありません。
標本数 N / seed16 / 170116個の実現値を、再現可能な乱数で作ります。
一様分布の仮幅を置く理由破裂高度の変化による影響を操作確認するため空欄では固定確認へ進めません。
  1. 標本と計算入力を固定して確認 を押します。
    標本・候補・必要時間窓を固定した計画が表示されます。まだ計算は始まりません。
  2. 固定気象が全候補の「放球から最大飛行時間まで」を覆うことを確認し、この固定計画で実行 を押します。
    予定・実行中・着地・停止などの件数が進みます。入力不成立は再抽選されず残ります。
  3. 結果ができたら この集合の候補を表示 を押します。
    この操作まで、地図は以前の固定結果のままです。 計算完了と表示切替は別です。
  4. 候補の「地図に表示」がONであることを確認し、50・90・95%経験輪郭と着地数を読み、この候補を詳しく → へ進みます。
    標本が少ない・一直線に並ぶなどの場合、輪郭は面にならず点や線になることがあります。

総試行数は「延期を含む候補数 × N」で256以下。同じ実現値で比べる候補は同じ固定気象を使います。入力を編集したら、固定計画を作り直します。分散は置いた仮幅に対する結果で、実測で校正した事故確率や気象誤差を含む確率ではありません。

元量とモデルの対応
変える元量対応する条件
ガス質量（kg）等温浮力を使う上昇モデル。一定上昇速度方式では使いません。
破裂高度（m）高度指定の破裂方式。径指定と取り違えないでください。
基準下降速度（m/s）基準速度を使う下降方式。

延期列：機体を揃え、放球時刻だけをずらす

親候補の ＋ 遅延列を作る で、まず ＋30分 を選びます。ダイアログ下の 選択した遅延の子候補を作成（未反映入力がある場合は 親と遅延列をこの入力で更新）を押して確定します。親から機体と気象を継承し、時刻差を持つ候補になります。

系列を作っただけでは計算されません。親の計算操作が親と延期列を対象にします。一飛行なら この条件で計算、仮幅なら再度計画を固定して実行します。仮幅の比較では同じ実現値が親子に対応します。

いちばん遅い子の飛行終了まで気象が必要です。

放球時刻だけが気象の有効範囲内でも不十分です。時間不足が出たら必要窓を含むGFSを取得・適用し、固定計画を作り直します。

03

今日・今後のGFSを取得して計算する

「今日のデータ」ではなく、予定する飛行の場所と時間を覆う予報を選びます。取得にはインターネット接続が必要です。

01配布を調べる使用する予報の初期時刻を選ぶ
02計画して取得範囲・時間・容量を確認する
03候補へ適用使用する気象を変更する
04計算して表示以前の結果とは別に作る
  1. 飛ばしたい条件を先に置く

    候補の 条件を編集 で放球地点、放球日時（JST）、最大飛行時間を設定します。延期を比較するなら子候補も作ります。

    ここでは旧保存気象の範囲外でも、取得するための草案として条件を決めます。まだ計算しません。
  2. 対象候補と配布を調べる

    共通の準備 → 気象の準備 → GFS予報を取得する を開き、気象を適用する候補 で親候補を選びます。延期子も対象になります。通常は 調べる初期時刻（任意・UTC） を空欄にし、配布一覧を更新 を押します。

    この版では空欄時に直近2初期時刻を調べます。空の一覧は、全ての配布が存在しないという意味ではありません。
  3. 使用する予報を選ぶ

    使用する初期時刻（UTC） を選びます。飛行より後に初期化された予報は使わず、必要な全時間窓が配布されているものを使います。

    GFSの初期時刻は00・06・12・18 UTC。日本時刻はUTCに9時間を足します。気象の初期時刻と、放球時刻は同じにする必要がありません。
  4. 取得範囲と上限を決める

    対象地点を含む範囲へ合わせる を出発点に、予想する飛行全体を含むように範囲を調整します。取得計画を確認 を押し、時間・物理量・容量見積りを確認します。取得範囲を地図で確認 で境界も見ます。

    自動で合わせる範囲は放球点と余白です。軌道全体を必ず覆う範囲ではありません。上限超過は範囲などを見直してから再計画します。
  5. 固定計画で取得する

    この固定計画で気象を取得 を押し、「保存済み」または資産再利用の完了を待ちます。

    取得済みファイルは照合の上で再利用します。応答が見えないときは「状況を確認」で観測し、別要求を連発しないでください。
  6. 気象を適用し、地表を確認する

    完成した気象を選択候補へ適用 を押します。地点や気象を変更した場合は この地点・時刻のモデル地表を確認 で放球高度との関係を確認し、必要なら 地表＋指定高さを放球高度へ反映 を使います。

    機体条件を保って使用気象が替わります。地表高度はモデルの値で、現地実測の標高そのものではありません。
  7. 改めて計算・表示・保存する

    一飛行なら この条件で計算。仮幅なら 標本と計算入力を固定して確認 → この固定計画で実行 → この集合の候補を表示 へ進み、最後に 計画を保存 します。

    気象を取得しただけ、適用しただけでは、旧結果は更新されません。
放球は任意時刻、気象は配布時刻です。

飛行時刻を気象の時刻に揃える必要はありません。対応する複数時刻の場を内挿して計算します。ただし、放球から設定した最大飛行時間まで、気象の支持範囲に入る必要があります。

04

結果を掘り下げ、保存して戻る

落下を避ける領域と比較

共通の準備 → 落下を避ける領域 → ＋ GeoJSON / KML を追加 から領域ファイルを取り込みます。

着地した標本との干渉数を読み、干渉群を詳細へ渡して履歴を調べます。着地点との干渉であり、飛行中の空域侵入を全て判定する機能ではありません。

履歴を読む

この候補を詳しく → を開きます。全標本から、地図で絞った群・干渉群へ対象を替えて履歴を比較します。

詳細の時間バーは表示する時点を変えるものです。入力を変えて再計算する操作とは別です。図を渡すときは詳細画面の PNG保存・SVG保存 を使い、ダウンロード先にファイルができたことを確認します。

写真3Dは必要なときだけ接続する

3Dで周辺を確認 から写真3D画面へ進み、Google Map Tiles APIキーを入力して Google写真3Dへ接続 を押します。基本の計算・2D表示にGoogleキーは不要です。

軌道＋地表線 は一組で表示し、カーテン で両者を結ぶ幕を切り替えます。軌道全体を見る で経路全体を見渡せます。分散面や禁止領域の面にカーソルを静止させると名称を確認できます。

キーはこの配布物に含めません。画面への入力と接続は利用者が行います。不要な再読込み・再接続は避けてください。解析モードや保存計画の切替で3D画面が作り直される場合は、再接続が必要です。

保存と再開

  1. 必要な結果・表示対象を選び、読込み完了後に上部の 計画を保存 を押します。
  2. 次回も同じ保存先・同じURLで起動します。
  3. 保存結果を開く → 保存した計画を読み直す で戻ります。保存した集合は 固定集合を表示 で選べます。
保存計画の読込みは、今の未保存草案を置き換えます。

残したい変更があるなら先に保存してください。図やKMLの書出しは結果の共有用で、別PCへ計画一式を自動移送する機能とは異なります。

05

付属の実気象で、年間・季節の特徴を見る

このZIPには、2024年のJRA-3QとERA5について、各4元格子の風統計デモを同梱しています。

  1. 気象を分析 → 保存した実気象集計 を選びます。集計する資料 からJRA-3QまたはERA5の2024年原標本を選びます。
    資料が出ない場合は、初回デモ展開と起動時の登録を確認してください。
  2. 資料の対象年を確認し、範囲・時間帯を選び、この対象で再集計 を押します。
    この版では年の部分選択はできません。対象を変える操作は明示適用です。描画済みの図が、未適用の編集内容へ変わったとは限りません。
  3. 年間の高度構造、季節による分布、地域差などを切り替えます。気圧面スライダーは自動更新です。
    短い待機を挟んで更新し、計算中は直前の図を保持します。新しい図の対象・気圧を確認して読みます。
  4. 図が決まったら SVGを準備 → 生成済みSVGを保存 をクリックします。
    リンクを生成する操作と、ファイルを保存する操作は別です。
この付属原標本で選べる時間の区切り
区切り意味
48区分年間の高度構造だけで選べます。UTCの各月を1–7日／8–15日／16–22日／23日–月末の4区分にします。
24 / 12 / 4区分半月／月／季節。年間図・地域図など、対応する図で粒度を選びます。「中央値と月の幅」は12か月固定です。
時間帯フィルターUTC 00・06・12・18時の解析時刻を選びます。日本の暦日や、任意の時刻幅を指定する機能ではありません。
見られる範囲を、資料ごとに区別します。

このデモは4格子・1年の操作確認用です。全北海道・10年の統計や多年を代表する季節の落下分散は含みません。別資料の10年DBは期間集計であり、同じ48区分へ自由に分割できる原標本ではありません。

風統計だけでは温度・湿度・高度を含む飛行用の瞬時場は揃いません。統計画面から関心を渡す操作と、任意の過去日時で実際に飛ばせることを区別してください。

普段の起動と終了

08

何を渡し、どこへデータが保存されるか

場所入っているもの共有との関係
展開したZIP計算・API・画面・テスト・ツール、全登録文書・記録・参考資料、GFS/JRAの飛行例3件と2024年JRA/ERAの風統計例利用・開発資料を含む固定スナップショットです。Git履歴自体は含みません。
自分のPCで作る環境backend/.venv、frontend/node_modules、frontend/dist初回手順で作成。ZIPに入っていません。
自分のPCの保存領域計画、計算履歴、後から取得したGFS、展開した風統計例GitやこのZIPへ自動で入りません。

この手順で起動した場合の保存先

エクスプローラーのアドレス欄に %LOCALAPPDATA%\SpaceBalloonSimulator\standalone-059 を貼り付けて開けます。

%LOCALAPPDATA%\SpaceBalloonSimulator\standalone-059\
├─ climate-demo\          JRA-3Q / ERA5の展開済み風統計例
└─ state\                 計画・結果・取得した気象
   ├─ registry.sqlite3    計画と計算の台帳
   ├─ weather\
   │  ├─ registry.sqlite3        気象取得の台帳
   │  ├─ inventories\…          配布一覧の記録
   │  └─ acquisitions\取得ID\
   │     ├─ fXXX.grib2          取得した原ファイル
   │     ├─ weather.json.gz     計算用に変換した気象場
   │     └─ receipt.json など   来歴・照合情報
   └─ results\計算ID\     個々の計算結果

上は主要な配置です。集合や気象分析には別の台帳・成果物も作られます。保存先は BALLOON_DATA_DIR に従います。未指定時の既定は %LOCALAPPDATA%\BalloonSimulator\state で、上の配布手順とは異なります。

外部の人に「まず試してもらう」場合

今回のZIPを一つ渡し、このHTMLから始めてもらえば、付属例の利用に自分のstateを追加で渡す必要はありません。 受け手の初回環境準備は必要です。取得済みの新しい予報や、自分が作った比較計画まで同じ状態にする用途は別です。

別PCへの計画一式の自動import/exportは、この版では未実装です。稼働中stateのコピーを通常の移送手順にはしません。10年DBや広域の取得束もZIPには含めていません。開発に参加する人には、権限のある非公開リポジトリの固定版で仕様と履歴も共有できます。

必要な通信・キー

初回依存導入、新規GFS取得、背景地図・航空写真には通信を使います。保存気象の飛行計算やこの手引きの閲覧に、新しい気象取得は不要です。Googleキーは写真3Dだけに使い、配布物へ含めません。

09

困ったときは、止まっている段階を確かめる

「標本と計算入力を固定して確認」が押せない

下端 < 上端、理由の入力、Nと総試行数、モデルと元量の対応を確認します。理由以外を埋めても有効になりません。ボタンのすぐ上の文章を読み、入力例と照合してください。

「この固定計画で実行」が押せない

固定計画に書かれた不足理由を読みます。気象の時間窓が全候補の飛行時間を覆わない、全標本が不成立、固定後に草案を変えた、といった原因があります。必要な気象を適用するか入力を見直し、固定計画を作り直します。

計算は終わったのに、地図が変わらない

集合なら この集合の候補を表示 を押します。表示中の固定結果と、今編集している草案は別です。新しい気象を取得・適用しただけでも地図の旧結果は変わりません。

送信担当ではない／「このタブで送信権を取得」が出る

このボタンは、同じアプリURLで計算・保存を送るブラウザタブを決めるものです。候補A/Bのタブとは別です。明示クリックで引継ぎます。処理中なら完了を待ち、もう一度押します。8秒無応答やWeb Locks未対応が表示された場合はその理由を控え、未保存の変更を残したまま別タブや別サーバーを増やして解決しようとしないでください。

GFSの配布が出ない／取得・観測が止まった

初期時刻はUTCです。直近2初期時刻の検索だけで見つからない場合は、調べる初期時刻を明示します。全飛行時間の配布があるかを確認してください。既存の取得では 状況を確認 で読直し、再試行可能な失敗なら 同じ計画を再試行 を使います。観測できないことは計算・取得の失敗とは限りません。

気象範囲を出て停止した／着地数が標本数より少ない

地図の取得境界と停止地点を確認し、必要なら範囲を広げて取得・再計算します。不成立・範囲外停止・取消を着地として扱いません。50・90・95%域は着地標本を対象にするため、着地数と全試行の内訳も一緒に読んでください。

起動時にpython / npmが見つからない

新しいPowerShellでバージョン確認を行います。Pythonは3.12系を指定し、npmは npm.cmd を使います。初回のエラー以降を飛ばして進めず、失敗したコマンドを確認します。PowerShellの実行ポリシーを緩める必要はありません。

画面が開かない／frontend/distがない

初回の npm.cmd --prefix frontend run build が成功したか確認します。起動端末のエラー、作業フォルダー、8451ポートの使用状況を確認してください。このHTMLが開けても、計算サーバーを起動したことにはなりません。

再起動したら計画や気象資料が見つからない

以前と同じ BALLOON_DATA_DIR、同じURLで起動したか確認します。風統計は BALLOON_CLIMATE_ARCHIVES のmanifestパスも必要です。データがないと決めつけてstateを削除したり、別の場所へ展開し直したりしないでください。
