# Chatと並行して設計材料を増やす

[更新:0.59.0] [確認:0.59.0] — RESEARCH-ENTRY / REV-590-CONTENT-RESEARCH-ENTRY

Chatには、**利用者の目的から現在の問題設定も問い直し、具体的な設計・研究でプロジェクトを進める仕事**を依頼する。Codexは資料を編集し、実物を確認し、回答を現行の設計・実装へ戻す。RPT-067/068、D-180/181に基づく分担である。0.41では局所課題を開始できることへ偏り、独立した判断に必要な全体文脈が不足した。今回は「何を知って、何を変えたいか」「なぜ現案へ至ったか」を先に共有する。

研究担当は資料束の表紙の課題IDを今回の焦点とする。初回はQ420-00を推すが、Q410-01〜05を渡された担当が00へ切り替える指示ではない。**焦点は作業量を区切るための提案で、考慮する全体や異論を制限する壁ではない。** 課題の統合・追加・優先順位変更が有益なら、理由と具体成果を伴って返してほしい。

2. 下の開始文を同じChatへ送る。PR13までを知る旧スレッドでも新規でも同じでよい。初回は全体を踏まえて重点を選び直し、選んだ判断を具体的に進めるQ420-00である。単なる全体の要約と次の宿題一覧は成果にしない。

人間が生成コマンドを実行したり、全資料を選び直したりする必要はない。[課題一覧](TASKS.md)と6つの資料束を用意する。実際のChatへの添付・開始と返却物の受渡しは人間が行う。**0.42作成時点では全課題が未発行、実Chat回答の受領は0件**。別担当の仮提案による内容批評は行うが、実Chatでの有効性とは分ける。実績は[指示書S35](../../BOOTSTRAP_RUNBOOK.html#S35)、[内容批評](REVIEW_042.md)、[BACKLOG T-017](../BACKLOG.csv)へ戻す。

## どう読むと研究の判断材料が得られるか

資料束にはこの節と次のPR13差分、[BRIEF](BRIEF.md)の目的と判断条件、[UI_WALKTHROUGH](UI_WALKTHROUGH.md)の行程、今回の問い、具体材料、返却の助けを収録する。発行・Git管理の手順は本READMEに置き、研究本文の前へ全て複写しない。共通本文を全課題へ含めるのは、入力だけ、気象だけ、保存だけを最適化して用途を壊すことを防ぐためである。原ニーズと現在案を分け、原図や原Excelが必要な結論は追加実体へ戻る。

例えばQ01ではWeibullの一般解説より、既存の製品径と膜厚幾何の不一致が何を意味し、同じ計画のモデル比較をどう変えるかを調べる。Q03では95%楕円を描くだけでなく、少数標本や多峰性で禁止域への関係がどう読めるかを考える。Q05ではDBの選定だけでなく、新予報で更新した後に旧図を読み直す人が何を再現できるかを設計する。原案を守るために問題を狭くする依頼ではない。

## Codexと発行担当：渡す資料と、その時点を固定する

[生成済み資料束](packets/manifest.json)は課題別の入口・依頼・必要本文・返却形式をまとめた読みやすい派生物で、設計正本ではない。元本文のパス、対象範囲、版とhashへ戻れる。編集元は本README、TASKS、RESPONSE_TEMPLATE、[抽出指定](packet_sources.json)、各担当本文である。[生成器](../../tools/build_research_packet.py)で再生成する。資料束の本文を直接直すと、次の生成で失われる。

Codexは配布前と元本文を改訂した後に、repo直下で `python -B tools/build_research_packet.py --check` を実行する。不一致なら `python -B tools/build_research_packet.py --output NEW_OUTPUT_DIR` で未使用の出力先へ生成し、各課題の内容と差分を読んでから登録済みの7生成ファイルを更新する。生成器は既存出力先への上書き、指定範囲の欠落、repo外の抽出元を拒否する。hash一致は抜粋の同一性であり、問いの十分性や科学的正しさの証明ではない。配布後の改訂は同じ束を無言で差し替えず、依頼版と変更点を新たに渡す。

作成時の比較元、依頼版、配布内容のhashと、後で人間が渡すGitコピーの統合SHAを別に記録する。ローカル`.git`の古いHEADを最新mainと推定しない。統合SHAが未記入でも、資料束の内容と作成基準に限定した研究は開始できるが、「現在mainを照合済み」とは言わない。

原資料を追加で読む必要がある課題では、TASKSに指定したExcel原ZIP、風PDF、コード等から必要な実体を添付する。原ZIP内を読めない場合は、Codexが対象章と依存する図を取り出し、元パス・hash・抽出範囲を付ける。Gitパスだけを書いて、ChatがユーザーPCを読めると仮定しない。公式説明でもChatGPT projectの資料はアップロード/接続したsourcesとされる。local projectは別の機能なので、実際の作業環境を最初に確認する（[OpenAI公式・Projects and chats](https://learn.chatgpt.com/docs/projects)、2026-09-28閲覧）。モデル名・契約・利用枠・費用は未確認であり、「GPT 6 Pro」「ほぼ無制限」はユーザーが示した利用想定として扱う。
